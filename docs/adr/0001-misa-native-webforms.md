# Receive MISA Leads Through Native Webforms and the KVC Server

Use official MISA Webforms on the Standard plan, with one fixed-owner form per active staff member, instead of upgrading to Professional for OpenAPI. Retain the KVC server action to validate input and consent, check the honeypot and spam patterns, and enforce the submission limit before forwarding a native POST. The user approved this adjustment after a smoke test showed that the Webform endpoint stored a request without a name when browser validation was bypassed. Do not create new consultation-request copies in Sanity; preserve historical data and unrelated MISA Webforms.

The most recent valid channel/CRM staff code pair within the same tab determines the link-attributed owner and referral source and survives navigation and reloads; an invalid or missing referral does not overwrite a valid pair, and stored values are only combined when they agree. A valid stored owner without a coherent source keeps that owner with a blank source. On submission, the KVC server revalidates both values and derives the CRM source ID from the allowlisted channel; the browser never supplies the numeric ID. Without a valid referral or retained authorized owner, use Nguyễn Hoàng Long (NV00005) as the default intake owner with no source. Accept only the nine active staff codes, excluding MISA SUPPORT and deactivated accounts. Link attribution does not establish that a consultation took place, nor platform or personal identity.

Map referral channels to CRM lead source IDs: zalo 8, facebook 9, instagram 10, telegram 11, x 12, tiktok 13, sent as strings. Send `LeadSourceID` only when the channel is allowlisted and the retained pair is coherent; an unknown but syntactically valid channel keeps the valid staff owner but leaves the source blank/default rather than inventing provenance. Add only verified IDs: a wrong ID mislabels CRM data.

The live website redirects `https://kvcglobal.vn` to `https://www.kvcglobal.vn`. Register new forms with the HTTPS origin `www.kvcglobal.vn`, not `.com` or a wildcard. Take form IDs and keys from MISA-generated HTML and keep them in a server-only module; do not execute MISA's exported inline JavaScript.

MISA redirects even when a submission is not stored and provides no record-level delivery receipt for native POSTs. The website therefore reports `submitted` (forwarded, awaiting confirmation), without claiming CRM persistence, emitting the GA `generate_lead` event, or automatically retrying and risking duplicates. The source cutover added `LeadSourceID` to the nine existing KVC Website forms; their owners, existing fields, form IDs, FormKeys, origins, redirects and activation settings were preserved. It did not change the subscription or data permissions, or deploy the website to production. A local production build was checked against live CRM for retained Telegram and TikTok referrals, X with storage denied during navigation, and a direct mobile visit with no source. The synthetic records were deleted after verification; evidence is recorded in `docs/misa-webforms.md`. Roll out CRM sources and form source settings before the website, then verify a known-channel lead and a direct visit after deployment.
